# Presentation and reproducibility checks

Use when reviewing a chart/table or the evidence needed to reproduce an analysis. Keep supplied artifacts unchanged; proposed corrections belong in findings.

1. **Match the display to the metric.** For each decision-driving figure, trace series/cells to source measures, transformations and filters. Check labels, legend, population, geography, currency/unit and scaling factors, denominator, sample size, window, as-of date and revision status. Distinguish percent from percentage points, counts from rates and nominal from inflation-adjusted values. If only an image is available, visual plausibility is not numerical verification; request values or code for exact reconciliation.
2. **Inspect encoding.** Check axis bounds, breaks, log transforms, unequal time spacing, bin definitions, cumulative versus period values and dual-axis comparisons. A bar's length normally encodes magnitude relative to zero; a truncated baseline can distort that comparison. A nonzero line-chart axis can be appropriate when clearly disclosed and not overstated. Log scales need explicit labels and treatment of zero/negative values; do not silently omit them. Check whether area/volume encodings or aspect ratio exaggerate differences. Treat an encoding as a finding because of its concrete interpretive impact, not a blanket chart-type ban.
3. **Inspect missingness and comparability.** Distinguish missing, suppressed, unavailable and zero observations. Do not let a connecting line imply observations across an unexplained gap. Check whether common axes and units support panel comparisons, whether category order changes the story and whether selected periods/groups hide a materially different picture. Compare confidence/prediction bands with their legend and method; absence of a band is not automatically a defect for a descriptive complete-population count.
4. **Check context and accessibility.** Ensure titles and annotations match the supported claim, uncertainty and causal limits. Source links should locate the actual dataset/release, not only an organization's homepage. Identify essential exclusions and provisional/revised status. Check readable labels, non-colour-only distinctions and a useful text alternative or accessible data table. Report observed accessibility issues without claiming a compliance audit or guarantee.
5. **Trace reproduction evidence.** Record input snapshots/releases and allowed access location, extraction/query revision, schema and units, filtering/joins, metric definitions, relevant timezone/locale, code/notebook revision, execution order, parameters, and relevant software versions/settings. For stochastic calculations request seed and randomness controls where applicable; a seed alone is not sufficient reproducibility evidence. Check whether manual spreadsheet steps, external dependencies, hidden notebook state or overwritten inputs break the lineage. Do not request secrets or copy personal records into review output.
6. **Evaluate sufficiency rather than presence.** Determine whether an independent reviewer can derive the claimed result from the supplied inputs and procedure. An attached notebook with missing inputs, a query against a mutable table without an as-of basis, or an image without values does not by itself establish reproducibility. Distinguish documented-but-not-executed reproduction from an actually authorized local recalculation and from source inspection alone. Request the smallest specific missing evidence; do not install dependencies, obtain access or rerun production to fill the gap.

Return the figure/table locator, observed issue or evidence gap, its effect on interpretation/reproduction and the exact correction/check needed.
