# Model Studio modeling path

## Technical source boundary

Applies-to source: **SAS Viya: Machine Learning User's Guide**, cover labeled **2025.10–2026.03***, dated **March 17, 2026**, [official PDF](https://documentation.sas.com/api/collections/vdmmlcdc/v_033/docsets/vdmmlug/content/vdmmlug.pdf?locale=en), consulted 2026-10-28. The cover's asterisk asks readers to check the Help Center version banner for other applicability; it is not blanket support. `v_033` is a documentation collection locator, not installed runtime evidence. The following UI details are bounded to this edition and must be checked against the actual target. Node-specific tuning options, score formats and compatibility outside its stated scope are not established here.

## Configure, fit, compare

1. Start from the entrypoint's agreed data/authority/partition contract. Record actual release and project identity; inspect available project/node settings against matching official help before changing them. When permitted, create a task-owned project or modify the explicitly authorized existing project. Do not import/upload data as a side effect of merely inspecting the design.
2. On the **Data** tab, assign roles and levels deliberately, recording the raw and formatted target levels and chosen event. Printed pp.109–113 describe **Role**, **Level**, **Order**, and **Specify the Target Event Level**. A nominal target's event can be specified; otherwise the first level after the configured ordering is selected. Formatted ordering can change the event without changing raw data. Confirm the actual event in model results, not just a familiar 0/1 assumption. A target is required for supervised project models, not a universal requirement for every analytical method.
3. For supplied partition variables, inspect **Order** and use **Map Partition Levels** to record every value's intended role. In this edition an existing partition variable's sorted levels determine assignment unless mapped. For raw levels 0,1,2 the documented descending example assigns 2=test, 1=train, 0=validation; ascending assigns 0=test, 1=train, 2=validation. Do not generalize those examples to arbitrary values or formats. Distinguish supplied labels from the generated `_PartInd_` variable: the documented generated indicator uses 0=validation, 1=train, 2=test. Verify resulting row/entity/time counts and mapping; a familiar variable name is not proof. The source's partition-role prose renders the name as `PartInd`; its examples use `_PartInd_`. Inspect the actual generated table/schema.
4. Record preprocessing as actual pipeline operations, not just metadata edits. Printed pp.109–111 state that Data-tab **Transform**, **Impute**, **Lower limit**, and **Upper limit** settings assign metadata rather than directly transform values. Verify the nodes consume the intended metadata, fit only allowed training portions, and preserve score-time transformations. A metadata setting alone is not preprocessing evidence.
5. Build a baseline and bounded candidates using available appropriate nodes. Inspect the selected node's matching-release official reference before naming node options or relying on its partition/encoding/scoring behavior; this general user guide does not establish every node's implementation. Capture pipeline graph, property values, partition/event settings and logs. With authorization, run only within the declared budget and inspect terminal node status, exclusions and diagnostics before accepting results. Failed/out-of-date nodes do not support a completed comparison claim.
6. In **Project Settings → Rules**, inspect the comparison selection statistic and selection partition; ensure these match the objective and do not expose final test to tuning. Printed pp.148–149 describe running a **Model Comparison** node before using **Pipeline Comparison**. By default Pipeline Comparison compares each pipeline's champion, not every model in every pipeline; inspect within-pipeline candidates via Model Comparison and record any additionally included challengers. Preserve the exact comparison population/statistic and any manual selection, not merely the champion badge.
7. Lock the chosen recipe and threshold, assess the protected test, and create the entrypoint's evidence artifact. A champion denotes configured selection, not governance approval. Printed p.152 onward describes registration and publishing separately: do not perform either as an automatic continuation. If score artifacts are authorized, inspect the model/node-specific scoring contract and compare keyed sample predictions with declared tolerances. Do not promise all models yield the same code format or support every scoring destination.

## Known delta: metadata propagation

The consulted edition describes a **2026.01** addition under **Project Settings → Node Configuration**: **Propagate variable metadata to the Transformations, Imputation, Replacement, and Filtering nodes**. It is unselected by default. The source contrasts earlier behavior, where these nodes receive Data metadata when directly below Data, with the optional propagation behavior. This is a documented delta, not a compatibility claim for every release.

Even when selected, propagation has exceptions: preceding Feature Extraction/Feature Machine; Variable Clustering using cluster-component representation; or Manage Variables overriding the relevant metadata. Binning/encoding transformations can change variable type and prevent downstream propagation of limits/imputation metadata; inverse transformations affect limits, while other transformations can transform propagated values. Inspect printed pp.110–111 and the target's pipeline/node help for the precise applicable case. Record effective downstream properties and learned transforms. Do not claim that enabling the option propagates all metadata through all pipelines.

## Target checks and uncertainty branches

- Unknown release: deliver roles/event/partition/pipeline/comparison plan; mark exact UI/option availability not established and do not apply edition-specific changes.
- Source and target differ: resolve the setting/node against target-specific official help and observed properties; document changed names/semantics before running. Absence from this guide is not proof of unsupported behavior.
- Wrong event, partition mapping or transform consumption: invalidate affected trials, correct the configuration under authority, and rerun only eligible development work. Report whether final test was exposed.
- Preserve project/pipeline/node IDs, source snapshot, settings and diagnostic evidence. Do not retain sensitive row exports merely to make a report reproducible.
