# Content promotion and mapping review

Load when inventorying or moving supported SAS content between environments. The [REST entrypoint](../SKILL.md) and its authentication/request references own HTTPS, authentication, pagination and uncertain-write handling. This branch supplies offline planning; execution needs separate authority and target-supported contracts.

1. **Bind both environments.** Record source/target deployment family, release/cadence/patches, installed CLI and transfer-plugin versions if used, explicit approved profiles/endpoints, content IDs/types and permitted effects. An omitted/default CLI profile cannot safely identify the intended environment. Distinguish content transfer from CAS table promotion, MAS/SCR publication and full-system migration.
2. **Inventory supported scope.** Use target-matched migration guidance to inventory exact resources and supported dependencies. Preserve source IDs/revisions and target collision/mapping evidence. Content files do not imply migration of CAS data, credentials, authorizations or external resources. The inspected official edition covers 2020.1.4–2026.01 and supports same-or-later release targets, not reverse migration. An unknown or older target requires supported-version evidence before execution; that edition cannot establish support for a later source/target pairing either.
3. **Prepare an allowlisted manifest.** List package/resources, artifact checksums where files exist, source-to-target mappings and an explicit authorization-migration decision. When authorization migration is not requested, exclude it using the target-supported equivalent of `options.promoteAuthorization=false`, verified against installed help/documentation. This option does not prove target effective permissions are correct. Keep existing target content untouched until replacement is explicitly approved; resolve collisions first. Do not import every JSON file in a directory, silently replace resources, suppress confirmation quietly or disable TLS verification.
4. **Review utility hazards, not a wrapper.** In the pinned `importpackages.py`, all matching files are imported with a replacement warning; shell commands lack checked return codes. Its combined mapping/exclude-authorization branch can overwrite the supplied mapping and use a different temporary path. `gettransfermapping.py` uppercases connector type but compares User/UserGroup using mixed case, so its output is not authoritative proof that those mappings survived. Utility output or exit success alone cannot establish completion. Do not adapt these scripts merely to produce a plan.
5. **Verify each separately authorized stage.** Distinguish export creation/download, upload, import completion and resource validation. Preserve job/package/import IDs and partial outcomes. Reconcile any prior uncertain import before retrying. Require identity/revision/dependency checks, effective-access checks and approved business regressions after import; transfer completion is not runtime publication. Use scoped prior-state recovery, not deletion of all imported resources.
