# SCR runtime testing reference

Load only when reviewing/testing an explicitly selected SAS Container Runtime (SCR) endpoint or container artifact. SCR is not MAS and is not a prerequisite for ordinary REST/Compute or MAS work. The [REST entrypoint](../SKILL.md) owns authentication, trust and uncertain-write handling; [sources](sources.md#scr-testbench-sources) records the inspected example and rights boundaries.

1. **Bind the selected runtime.** Record actual SCR runtime/image identity (digest when available), architecture, selected model/decision source revision, module/endpoint/signature, dependencies, approved synthetic inputs/expected outputs and execution authority. The example's Viya 4 entitlement, registry credentials and Linux x86-64/Docker prerequisites are source observations, not proof of target compatibility. Do not log in, pull, build or start containers merely to read this skill.
2. **Separate artifact stages.** Generated decision code, `_module_definition.json`, a built image, a running service and verified business outputs are different evidence; none implies the next. The standalone example Dockerfile pins runtime `1.92.34-20241126.1732642908961`, a **2024 build**. The source commit does not recommend a supported image for a current environment. Verify target compatibility and provenance independently.
3. **Review generation/auth hazards.** Source `deploy.py` uses `verify=False`, persists local refresh-token material, overwrites generated files and generates code from a supplied decision flow rather than an explicitly pinned locked revision. Its parser-derived module identity does not prove the intended deployed revision. Require approved authentication/trust and explicit artifact/revision validation; do not adapt or execute this script as part of offline review. Keep credential values out of artifacts, logs and reports.
4. **Review exposure and dependencies.** Flag sample TRACE logging, passed headers and published host ports for review, not adoption as defaults. Use an already approved isolated endpoint/artifact for any later authorized test. Redis/Oracle variants require separately verified data connections, secret handling and image licenses; do not add or start either because the example includes them. Source Apache-2.0 terms do not license SAS runtime images or Oracle/Redis containers.
5. **Verify identity and business behavior.** Match the actual runtime contract and response identity/output to approved synthetic business cases. HTTP 200, successful container start and hello-world output are not fraud correctness. Identity mismatch fails verification even when transport succeeds. A MAS request shape is not automatically an SCR request shape. Lost responses remain uncertain until reconciled; no implicit replay or redeployment.

## Return

Return an offline identity/artifact chain, compatibility gaps, TLS/token/log/header/port review findings, dependency/license questions and an authorized-test/read-back plan. When execution is authorized, report actual endpoint/module/revision evidence and case-level output comparisons separately. Without that authority, state no login, pull, build, start, authentication or runtime test occurred; source examples do not establish Fraud Decisioning behavior.
