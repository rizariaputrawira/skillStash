# Visual Analytics report operations

## Applicability and completion evidence

Load when the reporting task includes pages/templates, layout/themes/accessibility, report state, recovery, printing/summaries, distribution/sharing/embedding, report packages, localization, user settings, data-driven-content URL mappings, promotion or sample reports. Basis: *SAS Visual Analytics: Designing Reports*, **2026.04–2026.05**, May 2026, `v_019-P1:vareports`, printed pp.4–86. This is a **Visual Analytics** procedure, not an SFD console procedure, SFD alert notification contract or proof that VA is installed alongside SFD. Modeling objects require the documented Visual Statistics/Viya entitlements; this manual is not a model-training/deployment guide.

Use [reporting and model handoff](reporting-and-model-handoff.md) for fraud metric/data contracts and Copilot boundaries. First bind the target VA edition, user role, report/folder/data identities, allowed change and destination audience. Missing menu entries can result from identity rules, license, selection or missing data; resolve those prerequisites rather than assuming a UI defect. This reference prepares actions under the skill's authority gate; it does not authorize installation, authentication, sharing, external posting, export or execution.

Finish the requested branch with the saved/prepared report and dependency identities, settings changed, intended audience/security context, source/snapshot/locale, expected versus observed results, and unperformed checks. A saved report, generated link, export job or scheduled distribution is not evidence of successful delivery or data authorization. The source was fully read as extracted text; screenshot review limitations are tracked outside this portable package in the source coverage record, not represented as UI execution.

## Access, interface and recovery

- From an existing authorized SAS session, the applications menu entry is **Explore and Visualize**. Sign out from the user menu signs out all SAS web applications, not just VA. Home contains folders, search and recommendations; recommendations are based on other users' activity, not accuracy approval. Quarantine review/lifting is an administrator/security-policy task, not a report-author workaround (pp.13–18).
- Use **Data** for sources/items, **Objects** for visualizations, **Outline** for page/object structure, **Suggestions** for selected-data suggestions and **Report Review** for performance/accessibility findings. **Options** applies to its selected report/page/object; **Data Roles**, **Actions**, **Display Rules**, **Filters** and **Ranks** have separate responsibilities. Object-level data/action syntax belongs to *Working with Report Data* and *Working with Report Content*, not inferred from this design manual. Outline can save object templates but cannot maximize controls/containers (pp.16–23).
- A PWA is an optional client installation, not a reporting prerequisite. If explicitly authorized, the documented path requires TLS/HTTPS, a Chromium browser and **Install SAS**; uninstall through the PWA menu. Default PWA session persistence can differ from browser behavior and administrator time-out configuration. Do not install it or prolong sessions merely to create a report (pp.12–13).
- After interruption, **Restore previous session** on Home recovers open saved and unsaved reports. Opening a new/saved report instead forfeits that recovered-session information. Autosave cannot be disabled; when another author has updated the report, choosing their updated report discards the recovered local changes. Compare revisions before choosing. Save normally afterward; recovery is not version control (pp.15–16, 48–49).
- Save names are limited to 100 characters without leading/trailing spaces. First save defaults to **My Folder**, later saves to the most recently accessed folder: explicitly confirm the destination. A saved report must contain a page. Open via Home/search/folders or toolbar **Open**; the first page appears and Data retains the source selected at save time (p.47).
- Delete a report from Home to move it to **Recycle Bin**; **Restore to previous location** reverses this, while **Permanently delete** is separate. Recycled reports still appear in search. Report-package deletion uses content deletion rather than a VA report-package delete action (pp.75–76).

## Pages, templates and layout

1. Choose the page purpose and type before wiring links. **Basic** is normal; a report needs at least one basic page. **Hidden** omits its viewer tab but remains designer-visible and can be reached through links; it is not a security boundary and cannot be the report's initial viewed page. Saving while on a hidden page opens the first basic page for viewers. **Pop-up** is an information window reached by an explicit object link; a page that originates page/report links cannot become a pop-up, and only URL links from an object in a pop-up are supported (pp.31–34).
2. Add using **New Page** in Outline or the page-tab add control; use the page menu **Page type** to change type. For pop-ups, select the page in Options and set window width/height percentages. Reloading pop-up/page data periodically can affect performance. Page data does not automatically refresh without the reload option unless a query is initiated; this is distinct from source freshness (pp.32–34).
3. If page visibility must be restricted, use **Limit visibility to specified users**, select members and deliberately retain or clear **Hide links to this page for users who cannot view this page**. Retain at least one nonhidden page with no visibility restrictions. Clearing the hide-links option leaves links whose unauthorized viewers receive a notification. Page visibility does not replace CAS/data authorization (p.34).
4. Reorder by dragging tabs or Outline; rename through the tab menu/double-click, Outline or Options **General → Name**. **Duplicate page** copies its objects too. Move objects by drag, Outline or toolbar **Move to**, choosing an existing/new page or beginning/end position as available. Review actions and filters after structural changes. Delete via the page menu or Outline only under the requested change (pp.35–36).
5. For **Import pages from report**, choose the source report and pages, then Import. Page/object settings and page prompts survive, but report settings such as theme/global display rules do not. Model-comparison pages cannot be imported. Reconcile sources, global filters/rules and report-level intent in the destination (p.36).
6. On an empty canvas use **Select a template**. SAS supplies six templates. Dashboard, Panel and Stack start with automatic one-way filters and filter breadcrumbs: inspect their actions before interpreting a fraud cohort. Custom templates work with themes and can be used for hidden/info pages, but cannot include model comparisons (pp.37–38).
7. To reuse a page, select **Save as page template**, name it and optionally choose a thumbnail. **Include data items** retains role assignments, rules, filters, ranks and sorting. **Include report theme** can change the theme of *every* page in the destination report; declining that confirmation cancels adding the template. Templates are creator-private by default; only administrators can **Make available to all users**, with visibility after a new/refreshed session. A hidden page receives the template name as page name; do not assume other pages do (pp.38–40).
8. Use **Manage page templates** to edit name/thumbnail/theme inclusion, administer publication, reorder by name/creation date or delete. Deleting a template does not delete existing reports but cannot be undone; recreate the template if needed (pp.40–41).
9. Keep the report focused: six or fewer pages is source design advice; more than twelve can cause performance problems, not a hard page limit. The default layout fits adjacent nonoverlapping objects to the screen and redistributes space when resized. Standard layout uses a 4×8 grid and precision layout a 10×10 grid; Ctrl increases resize resolution, while **Interface options → Disable layout guides** removes the grid. Container-specific behavior requires *Working with Report Content*. Inspect target desktop/mobile sizes: treemap tiling and collapsed/hidden legends can change with space (pp.11, 26, 30–31).

## Themes, options, state and accessibility

- Application themes change the SAS UI; report themes style report objects. **Settings → Global → General → Theme** selects the application theme. **Settings → SAS Visual Analytics → Report Defaults** sets the theme for new reports; it does not restyle existing reports. For a single report use **Options**, select the report, then **Style → Theme**. Light, Dark and High Contrast are documented choices; site custom themes require the Theme Designer/admin owner. Changing away from a legacy theme is irreversible through normal theme selection (pp.26–28).
- In Options select the report/page explicitly and use its search field to find settings. Report General exposes identity/author/timestamps, **Summary**, **Thumbnail object**, viewer-only **Periodically reload report data**, and **Disable persistence of report state**. The default thumbnail is the first object of the first page: avoid leaking sensitive content in a thumbnail (pp.42–44).
- Report style includes theme/background/font/padding/fill/line-marker/gradient/missing/other colors; object-specific padding/fill/line-marker/gradient/missing can override inheritance. **Data element style rotation** can rotate colors first or all attributes for accessibility, but does not affect fill-based graphs such as bar/pie charts. A fixed pixel report size is optional; assess viewport and scrolling before using it (pp.44–45).
- **Viewer Capabilities** distinguishes Simple edits, Comprehensive edits (the default) and Object data edits, plus **Allow insights**. These are view customization controls, not the read/edit sharing permissions or row-level security. Choose the least capability compatible with the report's intended interpretation (p.45).
- Viewer **Export** can Enable, Disable, or **Disable if private data is present**. With the conditional setting, data/Excel/image export depends on the object's private items; detail export is disabled if *any* source item is private because viewers can add columns. Package export checks private data in the report; PDF checks the selected report/page/object scope. Do not assume disabling one export path removes all other exposure routes (pp.45–46).
- Page Options include name/type/reload, padding, layout direction, **Avoid scrollbars**, and page-control placement. Report/page controls can be top/right/bottom/left; side placement can show more list values than the top/bottom drop-down presentation. Defaults affect newly created content; verify the actual report (p.46).
- By default each user's prompt/drill state persists across sessions; very large reports save state only on close. Administrator policy can disable persistence globally; the report's **Disable persistence of report state** forces its default state for all viewers. **Restore default report state** resets a view. Decide whether reproducible opening state or personalized exploration is intended; saved default state, current view state and distributed state are different (pp.11–12, 44, 55).
- Personal accessibility settings are global; viewer support varies between web, Android and iOS. Use **Report Review**, readable text descriptions/summaries, High Contrast where appropriate, and test the actual supported viewer/assistive technology when authorized. This manual points to *Accessibility Features*, keyboard shortcuts and release-specific mobile accessibility guides; it does not establish full accessibility conformance (pp.20, 28, 50).

## Printing and summaries

1. Select report toolbar **Export → PDF**, page menu **Export as PDF**, or object toolbar **Export → PDF**. Object export is unavailable for containers and objects in report/page prompt areas. Check export/privacy permissions before creating a persistent artifact (pp.50–52).
2. Set **Document Setup**: page size or explicit units/dimensions, empty rows/columns, contents, appendix, details tables, expanded clipped/nonvisible content, cover and accessibility tags. Expanded content prints applicable tables/crosstabs/gauges/containers on separate pages at the end. Cover metadata includes report/user/request date/page count; review that disclosure. Document Setup is saved with the report and reused for distribution, while **Select Objects** choices are not saved. Select exact pages/objects and Export (pp.52–53).
3. Preserve interpretation limits: hidden pages, prompts and prompt containers are omitted; data-driven/web content is omitted (static web rendering needs administrator Report Renderer Service configuration), authenticated image URLs cannot print, and containers normally print only the selected object. Scrollable table content may be incomplete unless expanded. Appendices carry descriptions/filters/warnings/errors/display legends and parameters where applicable, but high-cardinality filters can truncate. A PDF is not complete query evidence (pp.50–52).
4. Compare PDF to the intended state, especially distributed versus interactive output. Server fonts can differ; CFF fonts fail PDF generation and require an approved TTF replacement/conversion, not an unapproved third-party upload. Firefox new-tab/PDF handling and Edge locale rendering can need supported viewer/browser configuration; do not change global settings without permission (p.51).
5. For a summary, add a text object with static/dynamic text, then select it in report **Options → General → Summary**. Display through **About this report** or General while editing, and **About this report** while viewing; mobile apps can also display it. Explain population, time window, refresh and unresolved outcomes in a screen-reader-friendly summary, and ensure dynamic values reflect the intended filters. A manually authored report summary is distinct from a Copilot chart narration (pp.53–54).

## Distribution

1. Before scheduling, confirm report access for recipients, authorized export/data disclosure and delivery channel. Mail service and external URL require administrator configuration; Teams additionally needs Microsoft Azure and Environment Manager setup. These prerequisites are not performed by this reporting skill. The saved PDF Document Setup and saved **default report state**, not a viewer's drill/prompt state, determine distributed PDF content. Offline distribution uses global **Locale for offline processes**, not regional-formats/sorting locale (pp.54–55).
2. Open the report, choose **Distribute report**, create a distribution, name it and select users/groups and/or supported Teams channels. Set subject/message and whether to include PDF/summary (both normally included alongside a link). For Teams, select a team/channel with an email address; General is unsupported. Authentication or channel-email/security changes are separate authorized administrator/user actions, not an instruction to broaden email access (pp.55–59).
3. Treat destination security differently: email PDF generation runs separately for recipients to apply their row-level security; Teams PDF and summary run with the permissions of the person who last created/updated the distribution. Therefore reassess Teams disclosure whenever its editor changes, and never use recipient-specific email behavior to infer channel-safe content. The source's per-person project-time example illustrates recipient filtering, not a fraud data test (pp.58–59).
4. Set frequency, interval, time, time zone, start/end and active status in the schedule; save schedule and distribution. The source's last-day-of-month example is illustrative, not a recommended fraud reporting cadence. Users must have signed into the environment at least once to receive distributions, and newly signed-in users receive the next run. Record intended schedule and actual delivery evidence separately (pp.55, 59–60).
5. For immediate distribution, select the existing distribution and its run-now action, then confirm. Edit through the selected distribution's edit action; deactivate its schedule to unschedule; delete through its delete action and confirmation. Distinguish paused, deleted, attempted and delivered. **Save as** does not copy distributions; copied display-rule conditions omit recipients (pp.47, 60–62).

## Sharing, links and embedding

1. Save first, then **Share report**. Choose users/groups and **Can read** versus **Can read and edit**, inspect existing recipients and Share. Site configuration governs availability; by default My Folder/shared-with-you reports can be shared. An alert/home-page entry is not evidence of data access. Do not conflate sharing permissions, Viewer Capabilities, Model Studio project sharing or SFD alert handling (pp.62–63).
2. For **Copy link**, start at report/page/object toolbar/menu, select **Manage Permissions → People with existing access** or **Specific people**, then copy. Link-dialog choices persist between sessions: inspect rather than trust defaults. Report links can be interactive or images; page/object links are image-only in this manual. Objects on hidden pages can have links, reinforcing that hidden is not confidential (pp.64–67).
3. Use **Guest access** only when deployment and task policy permit it; it uses guest credentials and bypasses sign-in. Verify report *and data* as guest in a new session when authorized. A normal report link may open the installed iOS/Android app. For interactive report links, decide application banner/menu/page navigation visibility and defined URL parameters. If hiding page navigation on a multipage report, supply working page links. Review the generated URL/output because the manual describes banner/menu/navigation switches in terms of hiding them; do not infer checkbox polarity from label alone (pp.64–67).
4. **Copy embeddable markup** has parallel permissions/guest choices for report/page/object; the host page must load `va-report-components` from the SAS Viya SDK for JavaScript. Generated element types are `sas-report`, `sas-report-page` and `sas-report-object`. For reports, **Interactive report (SDK element)** versus image is explicit. Copy the target-generated snippet rather than inventing a host/authentication implementation from this guide; validate host origin, identity and data exposure under the SDK's actual documentation (pp.68–71).
5. The SDK overview distinguishes `va-report-components` (embedding/interactions), `content-components` (content browsing) and `sas-auth-browser` (browser authentication). Mobile SDKs customize apps/connections/subscriptions and MDM integration; those are separate implementation tasks. This design manual does not supply an SDK application/authentication procedure (pp.5–6).

## Report packages

1. Treat `*.sasreportpkg.zip` as a **data-bearing snapshot**, not a live report or promotion bundle. It contains report/images/styles/data/query results, including data needed for selected objects and their actions. Establish approved recipient, snapshot time, locale, retention and hosting before export. Prefer a relevant subset and basic objects; fetch the target edition's *SAS Report Package Reference* for object support and limits (pp.71–73).
2. Simplify advanced hierarchy interactions: avoid ranks, cumulative/percent-total/moving-average/suppression calculations, `suppress()`, `aggregateCells()`, `aggregateTable()` and `_FORALL_` contexts, and partial crosstab totals/subtotals. Use manual rather than automatic actions; avoid joins/aggregate sources/partitions/derived columns where possible. For advanced targets avoid linked selections, multiselect-list sources and heat-map sources; table/crosstab/graph action sources support single selection only. Report links, Esri premium and authenticated on-premises Esri are unsupported; packages are locale-specific. Do not silently remove required semantics just to make export succeed (pp.72–73).
3. Use **Export → Report package**, choose contents, persistence folder/name and overwrite behavior. **Save to SAS Content** persists indefinitely and creates a lifecycle obligation. Generation can finish after the session; an in-session result downloads to the browser destination, while the saved content can be downloaded through Environment Manager. Record actual artifact location/status rather than assuming receipt (pp.73–75).
4. Read `packageStatusReport.txt` inside the package for omitted objects/interactivity limits; messages are English-only. Reconcile snapshot values and supported actions with the live report. Deploy only to the approved web host with the SDK's release-matched instructions; unzipping to a web server is not authorization to publish protected data. CLI `reports build-package` scheduling is only a documented handoff here; obtain *Using the Command-Line Interface* before constructing commands or scheduling (pp.71, 75).

## Localization

1. Stabilize the original-language report first; keep translations UTF-8 and rich-text styling simple. Country-specific variants can use ISO language/country suffixes. Browser locale chooses the viewed report translation; offline distribution and package locale are separate. Inspect layout with the actual translated strings (pp.76–79).
2. Report name, reference-line names, source-locale currency/sorting, elaborate rich text and custom-group values are not fully localizable (group names are). Translation is not currency conversion or a change to data collation (pp.76–77).
3. For manual work, **Localize report**, choose translation language, edit Translation cells and confirm. For authorized available Copilot generation, **New translation**, choose language and generate; inspect alternatives and instructions (maximum 500 characters), deciding whether to replace pre-existing translations. Export TXT for human review. This in-context translation capability does not require opening the chat pane, and English-only chat does not imply that report translations are English-only (pp.77–78).
4. To work on an existing localized version, set browser language, open its localization table, edit/save or export text for approved offline editing and reimport. The manual warns that applying/importing localizations overwrites existing localizations: preserve the complete translation set before applying. CLI translation worksheets need the owning CLI manual, not guessed syntax. **Reset all translations** and **Delete all translations** are separate destructive choices; perform only the requested operation and confirm the retained result (pp.78–79).

## User settings and administered URL mappings

- **Settings → SAS Visual Analytics** changes per-user persistent settings; Close applies them and Reset restores defaults. Interface preferences govern applying viewing changes on return to editing and default expanded report/page controls. New-report defaults govern theme, titles, actions and control placement; they do not retroactively change existing content. Automatic object titles can change with assigned items and are unavailable for list tables/crosstabs/content (pp.79–80).
- Geographic preferences include default provider, distance units and approved Esri service/account use. OpenStreetMap is the documented default; object Map service can override where multiple providers exist. Esri account/service entitlement and SSO are site-dependent, and premium use consumes credits: do not accept terms or enter credentials as a report-style operation (p.81).
- Network defaults include hierarchical labels (ID versus ID plus column), node-size centrality and node-color metrics (centrality/community/disconnected network). Modeling preferences include p-value precision, descending-order event selection, two-level measure conversion (with default-data-view exception) and category/measure response statistics. These are VA defaults, not proof of an SFD event definition or approved model; bind the actual event and statistic separately (pp.81–82).
- Performance switches disable categorical cardinality, automatic correlations or outliers; disabling cardinality/correlations also removes Suggestions. Cardinality already displayed is removed after closing/reopening. Insight modes can be Automatic or Manual independently while editing/viewing. Prefer an intentional measured tradeoff over changing every switch. Themes can override all reports with High Contrast for the current user (pp.82–83).
- Shared third-party-visualization URL mappings require permission for `/SASVisualAnalytics/rest/customGraphTypes`. Under **Edit administration settings**, add label/URL pairs and confirm. Labels cannot contain `%`, parentheses, `<` or `>`. These mappings become selectable by all users; approve the destination, third-party data flow and administrator authority before changing them. No mapping is required to type a URL manually, which is not an exemption from policy (p.83).

## Promotion and samples

- Promotion/migration is an administrator branch under *Content Migration From SAS 9.4* or *Content Migration from SAS Viya*, according to origin. Move report dependencies, not just report files. Eligible categories include comments, data views, legacy explorations/graph templates under the stated release constraints, folders, files, reports, object templates, statistical models and themes; SAS 9 Visual Statistics project objects cannot directly promote to Viya 4. This manual is not a complete transfer command contract (pp.83–84).
- Older reports reconvert at each access until opened and saved in the new release; under change authority, save a reviewed migrated copy to address repeated conversion delays or older analytics-object print-toolbar issues. Preserve original evidence and recheck behavior before replacing the authoritative report (pp.84–85).
- Display-rule conditions migrate with a report, but notifications must be redefined. Data views and object templates are separate content under `/Products/SAS Visual Analytics/Resources/` and require administrator transfer; shared-default data-view mappings need administrator reassignment, personal defaults need user reassignment. Verify source bindings, themes, templates, notifications and data security in the destination (p.85).
- For an authorized sample exercise, **Data → Add data**, search **Library.name:** with `samples`, then add the chosen sample. The six documented assets are `COSTCHANGE.sashdat` (maintenance), `PROMO_EFFECTIVENESS_X_EFFECTS_2.sashdat` (promotion), `RAND_RETAILDEMO.sashdat` (retail), `SW_LAKE_RT_SENSOR_WATERQUALITY.sashdat` (lake sensors), `WARRANTY_CLAIMS_0117.sashdat` (repairs) and `WATER_CLUSTER.sashdat` (home consumption). Samples caslib assignment is site administration, not fabricated production data (pp.85–86).
- Home **SAS Content → Products → SAS Visual Analytics → Samples** contains **Retail Insights**, **Warranty Analysis**, and **Water Consumption and Monitoring**, based on the corresponding retail/promotion, maintenance/warranty and sensor/consumption pairs. Use these to learn UI behavior, not as SFD-ready fraud datasets or validated metrics. No sample report was opened and no sample data was loaded during this source-authoring work (p.86).
