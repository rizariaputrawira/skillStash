# Studio decision-data preparation

Load for reviewing supplied Studio data-grid serialization or lookup-import work. This preparation/review branch does not authorize arbitrary SAS execution, macro calls or bypassing MCP filtering. [Asset and lookup guidance](assets-and-lookups.md#lookup-edits-versus-activation) owns activation and consumer-impact policy; use it rather than treating an import as harmless data preparation.

1. **Resolve applicability.** Record actual product/release and availability of `DCM_SERIALIZEGRID` or `DCM_IMPORT_LOOKUP` through approved capability evidence. Upstream reports testing both examples on Stable 2024.12 and specifies Intelligent Decisioning 5.4+ for lookup import. These are source observations, not a Fraud Decisioning support promise or universal minimum. If macros or authorized execution are unavailable, complete an offline input/validation plan and state that no SAS serialization/import ran.
2. **Specify serialization.** Record explicit class/group keys, included columns/types/order, intended row order where business-significant, expected group/row counts, character lengths, null/blank semantics and encoding. CAS inputs must belong to the same session; a cross-session plan must be corrected before execution. The README's default maxima of 32,767 for SAS dataset output columns and 10,485,760 for CAS output columns are observed limits, not safe target sizes. Verify target configuration, byte-versus-character semantics and actual serialized length. Do not trim identifiers or business-significant blanks to fit. Fully parse the serialized text and verify target shape/schema; reject truncated or malformed output even if brackets balance or a validation flag says true. Compare decoded columns, rows and values with the source specification.
3. **Specify lookup import.** Resolve intended existing table/folder IDs, current/editable and active versions, approved key/value policy and duplicate/conflicting keys. Preserve string key identity: `001` and `1` need not be equivalent. Duplicate resolution and unknown-key handling require approved policy, not arbitrary deduplication. The source step matches by name/path and can create or update content; its activation checkbox defaults **true**. For an import/edit-only assignment, explicitly keep activation off and, after any separately authorized import, freshly verify that the created/edited version remains inactive. Never silently inherit the source default. Follow the containing activation owner before proposing any activation.
4. **Return the bounded result.** Report exact proposed/performed output identities, schemas, counts, length/parse/decoded-value validation, duplicate decisions, version/activation evidence and unresolved capabilities. Separate proposed effects from performed ones. Unknown applicability blocks execution/support claims, not the offline plan. No macro or MCP write is needed to review supplied material.

Pinned catalog, step README/implementation scope and no-incorporation boundaries are recorded in [SOURCES.md](../SOURCES.md). No step JSON, SAS macro/template body, screenshots or data is bundled.
